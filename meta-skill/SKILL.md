# Meta Skill - 元技能

## 概述

对话级别的元认知能力。在对话结束后执行复盘，目的是让技能体系持续进化：
1. 已用技能 → 发现优化点
2. 未形成技能的流程 → 判断是否值得沉淀为新技能

## 触发条件

**显式触发**
- `/meta-skill`

**隐式触发（识别关键词）**
- 复盘、回顾、总结这次对话
- 优化技能、升级技能、迭代技能
- 沉淀经验、提炼方法、提炼流程
- 这个流程可以复用吗
- 刚才的方法能不能存下来

## 执行流程

```
1. 对话分析
   ↓
2. 已用技能评估 → 输出优化建议
   ↓
3. 新技能判断 → 满足条件则输出草稿
   ↓
4. 等待用户确认 → 执行创建/更新
```

## Step 1: 对话分析

回顾当前对话，提取以下信息：

| 维度 | 内容 |
|------|------|
| 任务类型 | 本次对话完成了什么任务 |
| 使用的技能 | 调用了哪些 skill（列出名称） |
| 关键决策点 | 在哪里做了重要选择 |
| 意外/困难 | 哪里卡住了、怎么解决的 |
| 最终产出 | 文件变更、代码、文档等 |

## Step 2: 已用技能评估

对每个使用过的技能，对比实际执行与技能文档：

**检查清单**
- [ ] 是否完全按技能流程执行？
- [ ] 有无偏离？偏离是改进还是退化？
- [ ] 有无遗漏的边界情况？
- [ ] 有无可补充的示例？
- [ ] 流程是否可简化？

**输出格式**（直接输出，无需确认）

```markdown
## 已用技能优化建议

### [技能名称]
- **当前问题**: xxx
- **建议优化**: xxx
- **优先级**: 高/中/低
```

若无优化建议，输出"本次使用的技能表现良好，暂无优化建议"。

## Step 3: 新技能判断

对于未使用技能但重复出现的流程，评估是否值得沉淀。

### 准入门槛（任一满足即可考虑）

| 维度 | 问题 | 阈值 |
|------|------|------|
| 重复性 | 这个流程会再次用到吗？ | 预期 ≥2 次 |
| 复杂度 | 下次能凭记忆复现吗？ | 步骤 ≥3 或有隐性知识 |
| 时间成本 | 重新摸索要多久？ | ≥10 分钟 |
| 失败代价 | 做错了后果严重吗？ | 有不可逆操作 |

### 沉淀物分级

根据复杂度决定沉淀形式：

```
├── 规则（一句话原则）     → ~/.claude/rules/ 或项目规则库
├── 检查清单（步骤列表）   → 技能库/轻量级
├── 完整技能（流程+代码）  → ~/.claude/skills/
└── 工具脚本（纯自动化）   → tools/ 或 scripts/
```

### 输出格式（需用户确认）

```markdown
## 新技能建议

### 建议创建: [技能名称]

**触发场景**: 当用户 xxx 时

**满足条件**:
- [x] 重复性: xxx
- [x] 复杂度: xxx

**沉淀形式**: 完整技能 / 检查清单 / 规则

**草稿内容**:
[折叠的技能草稿或单独文件路径]

---
是否创建此技能？(y/n)
```

若无新技能建议，输出"本次对话未发现可沉淀为新技能的流程"。

## Step 4: 执行更新

**已用技能优化**
- 直接输出建议，用户可自行决定是否更新
- 若用户明确要求更新，再执行编辑

**新技能创建**
- 必须等待用户确认
- 确认后使用 skill-creator 流程创建
- 创建完成后同步更新技能索引（如有）

## 输出模板

完整的 meta-skill 输出结构：

```markdown
# 对话复盘报告

## 1. 对话分析
- **任务**: xxx
- **使用技能**: skill-a, skill-b
- **关键决策**: xxx
- **产出**: xxx

## 2. 已用技能优化建议
[直接输出，见 Step 2 格式]

## 3. 新技能建议
[需确认，见 Step 3 格式]

---
复盘完成。如需创建新技能，请确认。
```

## 注意事项

1. **不要过度沉淀** - 不是所有流程都值得变成技能，简单的一次性任务不需要沉淀
2. **保持技能精简** - 新技能应聚焦单一职责，避免大而全
3. **优先复用** - 创建新技能前，先检查是否有现有技能可扩展
4. **渐进迭代** - 技能可以从简单开始，随使用逐步完善
