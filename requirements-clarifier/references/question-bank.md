# Question Bank（最少追问问题库）

原则：
- 只问 3-7 个关键问题
- 问题要“可回答”：二选一 / 填空 / 给样本 / 给数字
- 优先问会影响方向与验收的

## Delivery（交付型）
1. 你最看重的结果是哪一个？（A 速度 / B 成本 / C 质量 / D 可扩展）
2. 交付物的形态是什么？（A 文档 / B 表格 / C 代码 / D 素材包）
3. 这次必须包含的 3 个点是什么？（列 3 条）
4. 绝对不能出现的 3 个点是什么？（列 3 条）
5. 谁来验收？用什么标准判定“合格”？（给 1 条合格样例或描述）

## Diagnosis（诊断型）
1. 现象是什么？（一句话 + 截图/数据区间）
2. 什么时候开始发生？最近有什么变更？（版本/配置/流程/渠道）
3. 影响范围多大？（多少用户/多少订单/多少页面）
4. 你希望最终得到什么输出？（原因列表/根因/修复方案/回滚方案）

## Decision（决策型）
1. 这次决策的唯一目标是什么？（只能写 1 个）
2. 你愿意牺牲什么？（A 成本 / B 时间 / C 体验 / D 风险）
3. 你绝对不能接受的失败是什么？（一句话）
4. 给 2-3 个备选方案（哪怕很粗），或者我来生成备选再让你选。

## Research（探索型）
1. 研究的用途是什么？（写报告/做方案/做产品/投资判断）
2. 你希望研究输出到什么深度？（A 概览 / B 可执行建议 / C 可落地方案）
3. 有无必须参考的信息源/样本？（给 3 个链接/关键词）
4. 截止时间和篇幅限制？

## Default Assumptions（常用默认假设）
> 当对方答不上时，用这些默认值推进

- 优先给“1页定义卡 + 10条打样”而不是直接大交付
- 验收默认：可读/可复用/无明显事实错误/结构一致
- 时效默认：先 2 天给打样，再进入批量
